# 시스템 구조 및 기능 명세

## 구조

```text
Emergent 상담 웹사이트
  ├─ 원본 상담 저장 / 기존 텔레그램 알림
  └─ 신규 상담 Webhook + 조회 API
            │
            ▼
Railway CRM
  ├─ Web: Next.js 모바일 대시보드
  ├─ API: NestJS + TypeScript
  ├─ PostgreSQL: CRM 운영 데이터
  ├─ Redis Queue + Worker: 이메일·동기화·재시도
  └─ Railway Cron: 예약 작업을 대기열에 등록
```

CRM은 별도 도메인/서브도메인에서 운영한다. 기존 사이트와 CRM은 데이터베이스를 직접 공유하지 않는다. 기존 사이트는 고객이 제출한 원본을 생성하고, CRM은 담당자·상태·활동·계약·청구 정보를 관리한다.

## API

### Emergent 연동

- 폼 제출 후 1분 이내 신규 상담 Webhook을 CRM에 전달한다.
- 전달 실패와 관계없이 상담 접수는 기존 사이트에서 성공한다.
- CRM 동기화 Worker는 5분마다 누락 접수를 조회·복구한다.
- 접수 ID를 idempotency key로 사용해 중복 생성하지 않는다.
- 기존 접수 이력 전체를 초기 이관한다.
- 원본에서 삭제된 상담은 CRM에서 삭제하지 않고 `원본에서 삭제됨`으로 표시한다.
- 양쪽 공유 비밀키 서명으로 요청 출처를 검증한다.

### CRM 외부 API

AI 에이전트가 첫 대상이다. 전용 서비스 계정별 권한을 발급한다.

- 회사·영업·활동·다음 행동: 직접 반영 가능
- 계약·계산서·입금·환불: 승인 요청 후 반영
- 사용자·권한·시스템 설정: 외부 AI에는 불허
- 일괄 등록·상태 변경 API 제공
- 외부 변경도 전체 감사 로그 보관
- 신규 상담, 상태·담당자 변경, 다음 행동, 계약서 서명, 계산서·입금·환불, 장기 보류·실패 이벤트를 Webhook으로 발행
- API 버전은 최소 6개월 유지한다.
- 기본 한도는 분당 120회, 일일 10,000회다.

## 인증과 권한

- Google Workspace 로그인
- 첫 로그인 사용자는 열람자로 자동 등록
- 역할: 관리자, 열람자, AI 서비스 계정
- 관리자는 역할·휴무·Webhook·장애 알림 채널을 관리한다.
- 열람자는 계약·계산서·입금 정보를 포함해 읽기 전용으로 조회할 수 있다.
- AI 서비스 계정은 부여된 API 범위만 사용한다.

## CI/CD와 운영

- GitHub: Pull Request → `develop`(검토) → `main`(운영)
- GitHub Actions로 검사·배포 파이프라인을 실행한다.
- 운영 배포는 본인의 GitHub 승인이 있어야 진행한다.
- Railway는 싱가포르 리전을 사용한다.

## 복구와 장애 대응

- 최대 허용 중단 시간: 반나절
- 최대 허용 데이터 손실: 하루
- 매일 DB 백업, 주간·월간 백업 추가 보관, 외부 논리 백업, 분기별 복원 시험
- 장애 알림은 발신 전용 Gmail이 실패해도 보조 이메일과 범용 Webhook을 통해 보낸다.
- 모든 사용자·AI·자동화 작업 이력은 계속 보관한다.
- 접수 ID가 다른 유사 상담은 자동 병합하지 않고 `중복 의심`으로 표시한다.
