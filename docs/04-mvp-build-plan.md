# 6차 프로세스 · MVP 구축 및 검수

서비스명: 굿모닝테라유림부동산 CRM  
시작일: 2026-10-18 (KST)

## 진행 순서

1. **MVP 범위 구축**: 실제 사용 흐름이 가능한 화면·API·데이터 모델을 만든다.
2. **구축 검수**: 로컬 실행 화면에서 담당자가 시나리오를 따라가며 검수하고, 피드백을 반영한다.
3. **안정화 및 배포**: 타입 검사·빌드·핵심 흐름 검증을 CI에 넣고, Railway 스테이징과 운영을 순서대로 연결한다.
4. **추가 구축**: AI 자동화, 외부 API, 분석·운영 편의 기능을 별도 검수 단위로 확장한다.

## MVP 포함 범위

- Google Workspace 사용자 진입 화면의 자리 및 권한별 화면 경계
- 오늘 할 일: 4개 KPI, 우선 처리 목록, 전화·완료·위임 행동
- 영업판: 상태별 목록과 영업 건 상세 이동
- 신규 영업 건 등록: 회사·담당자·연락처·관심 서비스·상담 내용
- 영업 건 상세: 접수 정보, 활동 이력, 다음 행동 기록
- 계약·청구: 발행 예정과 미수금 목록
- 관리: 사용자·권한, 휴가·위임, 외부 연동 설정의 진입점

## MVP 제외 범위

- 실제 Google OAuth, Gmail 발송, Google Drive 접근
- Emergent 운영 웹훅과 5분 누락 동기화
- AI 에이전트 실행과 사람 승인 흐름
- 실제 계약서·계산서 발행 및 외부 Webhook 전송

위 항목은 화면·데이터 모델의 확장 지점을 남긴 뒤, 안정화 또는 추가 구축 단계에서 비밀값과 운영 계정을 연결해 구현한다.

## 1차 MVP 검수 시나리오

1. 오늘 할 일에서 기한 초과·오늘 연락·신규 현황을 본다.
2. 우선 처리 카드에서 상세로 들어가 상담 정보를 확인한다.
3. 전화·완료·위임 행동을 실행해 활동 이력과 상태 변화를 확인한다.
4. 신규 영업 건을 등록하고 목록에 추가된 결과를 확인한다.
5. 영업판과 계약·청구에서 같은 영업 건의 상태를 확인한다.

## 안정화·CI/CD 기준

- TypeScript 검사와 프로덕션 빌드가 Pull Request 및 `develop`, `main` 푸시에서 통과해야 한다.
- 이후 핵심 사용자 흐름의 자동 검증을 추가한다.
- `develop`은 Railway 스테이징, `main`은 GitHub 승인 후 Railway 운영 배포의 기준 브랜치로 사용한다.
- 운영 환경 변수와 외부 서비스 키는 저장소가 아닌 Railway 환경 변수로 관리한다.

세부 절차는 [CI/CD · Railway 배포 검수](05-deployment-runbook.md)를 따른다.
